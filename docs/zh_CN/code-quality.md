# 代码质量审计与 API 设计说明

本页记录截至 7.1.1 的代码审计结论，方便维护者理解现有结构、API 选择及后续重构优先级。运行环境只支持 Paper 1.21.11 + Java 21，不为旧 Minecraft 版本、Spigot 或 Folia 保留运行分支；附属插件 API 的兼容策略与服务端版本兼容是两件独立的事。

## 本次已经改进

### 结算状态只有一个玩家模式所有者

7.1.1 把结算参与者恢复集中到 `Arena.changeStatus(restarting)` 的单一入口，并固定在状态赋值之后、`GameStateChangeEvent` 和 Sidebar/TAB 重建之前执行。死亡重生会话、第一人称观战目标、真实游戏模式、拾取能力、飞行状态和结算物品在同一批次完成；正常胜利、超时和无人存活不再各自维护不完整的结束分支。`GameEndListener` 只处理与玩家状态无关的世界掉落物。

PlayerInfo 的 `UPDATE_GAME_MODE` 只用于“其他查看者眼中的 TAB 行”。目标就是查看者本人时不发送伪旁观模式，旧缓存只允许恢复 Paper 当前真实模式。真实 `SPECTATOR` 仍只用于死亡等待或第一人称镜头，并且全部通过 Bukkit 模式 API 切换；重连不再另起延迟任务覆盖竞技场重生会话。这让客户端移动能力、服务端 `GameMode` 和反作弊观察到的权威状态保持同源。

结算排行榜快照也改由 Sidebar 自身在 `restarting` 生命周期内创建和释放，不再由可选的聊天输出循环注入。配置关闭聊天排行榜不会改变侧边栏解析能力，下一局也不会继承上一局统计对象。

### 喊话格式与游戏时间不保存多余计时状态

7.0.0 删除 `/shout` 的到期时间表和冷却分支。PlaceholderAPI 的喊话标记改为仅在当前异步聊天格式解析调用栈内存在的 `ThreadLocal` 上下文，并在 `finally` 中恢复上一层值；不同线程、不同玩家和异常路径不会互相污染，也不会长期保留离线 UUID。

TAB 的本局时间直接读取竞技场已经维护的 `startTime`，由现有页首页尾刷新任务求值并经过完整内容缓存去重；没有新增调度器、全服实体扫描或第二份比赛计数器。通用渲染器先检查当前文本是否实际包含占位符，再调用其供应器，因此不会对页首页尾每一行重复计算无关动态值。TAB 与 `%bw1058_elapsed_time%` 共用无 `Formatter` 分配的纯格式化器，避免边界行为分叉。

### 世界环境使用 1.21.11 原生规则和事件守卫

6.0.0 不再把旧 Bukkit 规则名直接转换成看似正确但实际不存在的注册键。时间、天气、生物生成、随机方块刻、火势范围和 Locator Bar 等插件不变量直接使用 Paper 1.21.11 的类型化 `GameRules` 常量；竞技场 YAML 仍可写历史名称，由一处显式别名映射兼容。世界范围策略也与竞技场自然方块规则分离，大厅只获得正午和晴天，不会连带关闭随机刻或自然方块变化。

监听器先完成注册，再一次性处理插件启用前已经加载的世界；之后只响应世界初始化/加载、时间跳跃、天气和游戏规则变化。`MULTIARENA`/`BUNGEE` 覆盖专用实例全部世界，`SHARED` 实时识别竞技场、恢复队列、设置会话和配置大厅，不维护可能在重置后过期的世界名缓存，也不增加逐 tick 扫描。CI 在固定 Paper 1.21.11 build 132 的补丁服务器类路径中直接读取注册表，防止 API 编译通过但生产键名再次漂移。

### 不再要求附属插件依赖内部组队类

开局邀请组队原来只存在于 `bedwars-plugin` 的 `PreGameSquadManager`，附属插件无法在只依赖 API 模块时调用。现在新增 `PreGameSquad` 服务，并通过 `BedWars#getPreGameSquadUtil()` 暴露。

返回的成员和可邀请玩家列表均为不可变快照，调用方不能破坏内部队伍状态。

### 提供安全的竞技场查询

旧方法可能返回 `null`，竞技场列表还是内部 `LinkedList`。为保持二进制兼容，旧方法没有删除；新代码可使用：

- `findArenaByPlayer`
- `findArenaByName`
- `findArenaByIdentifier`
- `getArenasSnapshot`

这样能减少空指针和附属插件误删内部竞技场的问题。

### 补全配置访问 API

`Configs` 新增等级、经济奖励和声音配置入口，附属插件无需引用实现模块的静态字段。

### 大厅状态成为明确 API

`applyLobbyState` 统一应用冒险模式、飞行、拾取和大厅物品。它与只刷新物品的旧方法分开，避免 API 名称和实际副作用不一致。

### 配置文档集中管理

所有中文配置说明集中在 `ChineseConfigDocumentation`，配置架构升级时统一写入旧文件。竞技场动态队伍在每次保存前重新补注释，避免新建队伍没有说明。

### 方块生命周期职责拆分

`BreakPlace` 原来同时负责建造权限、床破坏、爆炸保护和玩家放置方块索引维护。2.10.4 将索引的添加、删除、爆炸/燃烧/褪色清理、重力方块迁移和活塞保护提取到 `PlacedBlockListener`。这样权限逻辑与方块生命周期可以分别审查和测试，也避免继续扩大已经较长的监听器。

### 热路径与背包监听清理

- 建图会话由 `List<Player>` 改为 `Set<UUID>`，查询为平均 O(1)，并在退出时清理。
- 位置保护判断统一使用同世界平方距离，保护半径只读取一次，不再用宽泛异常捕获掩盖错误。
- 删除没有任何副作用的关闭背包全量扫描；受保护物品移动改为单一路径判断，并补全拖拽和副手交换。

### Paper 1.21.11 热路径收敛

- 玩家移动事件先用 Paper 的位置、方块和区块变化标志短路。转头不再进入 AFK、基地、虚空、床悬浮字和全地图悬浮字逻辑，跨区块判断直接比较方块坐标，不解析或加载 `Chunk` 对象。
- 每局开局时建立玩家 UUID 到队伍的只读索引；仍可能变化的等待阶段和异常状态保留线性回退，淘汰后的原队伍由同一局快照查询，避免改变 API 语义。
- 资源生成器和火球只查询邻近的 `Item` 或 `Player`，不再取回无关实体后做流式过滤。资源堆叠在创建实体前完成，`spawn-limit` 则累计物品堆叠数量，避免性能优化改变产量上限语义。
- 不会在运行中热更新的交互开关、特殊商品属性和生成器分流开关在监听器或生成器初始化时读取一次。声音直接以玩家实体为声源，商店、陷阱、伤害与侧边栏复用单次队伍查询结果。
- 这些路径直接使用 `Material.FIRE_CHARGE`、`Material.CRAFTING_TABLE`、`World#getNearbyPlayers`、`World#getNearbyEntitiesByType` 等 1.21.11 API，不再经旧版本材质桥接层。

### 开局策略与火球计算可独立测试

2.10.5 将固定的“两名玩家、两支非空队伍”要求集中到 `ArenaStartPolicy`，删除散落在等待、离开和组队流程中的 `minPlayers`/队伍状态复合条件。火球击退计算也提取为不修改输入向量的纯函数，避免事件循环中的顺序依赖，并允许直接做方向回归测试。

2.10.54 进一步让开局策略只验证本局启用队伍，未被分配的配置队伍可以为空；满员要求从资格判断中移除。火球初速度、潜行倍率、持续加速度、三维反向后坐力和冷却边界计算集中到无 Bukkit 副作用的 `FireballLaunchPhysics`，其中后坐速度被硬限制为 0.20。

3.0.0 不再使用 Paper 已弃用且实际返回加速度的 `Fireball#getDirection()` 计算初速度。8.0.0 进一步绕过 Paper 1.21.11 会覆盖当前速度的 Bukkit `setAcceleration` 实现，通过版本支持层只修改 NMS 持续加速度字段：普通火球保持 1.6 初速度和 0.1 加速度，潜行火球使用 2.4 初速度和 0.2 加速度。CI 会在固定 Paper 运行时反射验证字段契约，避免补丁升级静默重新抹掉初速度。

5.0.0 为了执行真实的 200–300 格随机射程，给每颗火球建立一个随实体调度器运行的轻量任务，只保存上一位置和累计路程；火球碰撞、移除或达到上限后任务随实体结束，不维护全局火球表，也不扫描世界实体或加载远处区块。火球敌方伤害使用带发射者的 Paper `PLAYER_EXPLOSION` DamageSource，死亡解析直接读取当前伤害源，不再从 `CUSTOM` 原因或较早的普通攻击猜测来源。

竞技场 TAB 的页首页尾、状态化前后缀与排序继续以 `andrei1058/BedWars1058@669872626ec4160b6896755ba1d79bbed96787fb` 为布局基准；大厅与竞技场全部状态统一拓宽到至少 128 空格。4.0.5 恢复同一 scoreboard Team 同时负责 TAB 和头顶名牌，PlayerInfo 的 nullable 显示名只负责允许客户端进入 Team 渲染分支，不再保存第二份颜色和文字状态。

4.0.3 将 TAB 文字与头顶名牌分成两条明确链路：每个查看者收到一个包含前缀、明确队伍色玩家名和后缀的 PlayerInfo 显示名，不修改目标玩家的全局 `playerListName`；每个查看者的 scoreboard team 只负责头顶颜色、成员关系和名牌可见性。反射成员在启动时解析并缓存一次，普通状态变化只发送内容确实变化的行；`showPlayer` 重建只重放一个目标行，周期自愈按查看者合并为一个批量包。同一次刷新先求值一次动画文字，再复用于所有观察者及两条链路。退出上下文或插件卸载时使用服务器当前值恢复，活动 Sidebar 所有权会阻止旧实例覆盖新实例。

4.0.4 为公开 Sidebar API 补齐后进先出的观察者所有权链，并在中间层被移除或重新挂载时修复 scoreboard 回退引用。TAB 行的删除同时释放内部队伍名，替换玩家先删除旧 scoreboard entry；失败恢复保留去重目标并由下一次明确刷新重试，不新增周期任务。启动阶段不再只检查反射方法是否存在，而是实际构造并回读 `UPDATE_DISPLAY_NAME` 数据包；CI 使用固定哈希的 Paper 1.21.11 build 132 补丁后服务端运行同一探针。

4.0.5 删除逐查看者完整名称字符串缓存，改为缓存“PlayerInfo 名称已经清空”的目标 UUID；前后缀动画只更新 scoreboard Team。队伍解析集中为正式队伍、等待阶段预选队伍、历史队伍的明确优先级，并同时用于颜色与排序。选队刷新按事件传播到当前竞技场的 Sidebar，不新增扫描任务；竞技场最小队伍色上下文也不再与可选外观开关耦合。nullable 名称只通过逐查看者数据包管理，不调用全局 `playerListName` setter；恢复直接读取 Paper 当前状态，避免公开 Sidebar API 与第三方插件争抢全局名称。现有 TAB 事件和低频强制刷新同时检查实际 scoreboard 身份，只有发生所有权漂移时才重建并重新绑定，不增加逐 tick 扫描。

4.0.6 将服务器级玩家列表顺序直接建立在全部活动竞技场的实时队伍集合上，不再读取 waiting/starting/playing/restarting 的完整外观开关。最小队伍色模式和完整格式模式因此共享同一套同队聚合、队内字典序与光谱队序规则。客户端登录或跨世界确认时先根据实时世界重建 TAB 模型再重新绑定 scoreboard，避免 SHARED 模式两个 `arena == null` 世界误复用旧行。由于 Paper 1.21.11 普通跨世界不会再次触发 `PlayerClientLoadedWorldEvent`，监听器使用下一 tick 的事件驱动回调主动同步，并通过同一待处理标记与登录/重生加载事件去重。

4.0.7 收敛死亡与复活的单 tick 工作量。最终淘汰在成员状态提交后按竞技场合并刷新，侧边栏复用 objective 和行 Team，仅写入变化的标题、前缀和计分文字；可见性事件不会重复重放同一待淘汰 TAB 行，延迟执行前还会拒绝已离线、离场或换场的过期玩家。复活附魔先批量修改物品，再至多执行一次完整背包同步。安全出生点只访问当前已加载区块；加入告示牌保留兼容的可变 `List<Block>` API，同时由自维护索引把区块加载刷新从 O(全部告示牌) 降为当前及相邻区块候选，注册、文字与墙后支撑块写入均不会读取未加载区块。场外告示牌和 NPC 人数则离开观战数据包批次并按 tick 合并。Vault 的通用服务接口没有承诺任意经济提供者可从异步线程调用，因此击杀奖励没有用不安全的异步化掩盖第三方数据库延迟；若调用树指向经济实现，应修复或更换对应提供者。

4.0.8 将正常大厅流程的物品刷新收敛到受上下文保护的即时入口。登录、竞技场离场、跨世界进入和语言切换都会先确认玩家在线、未进入竞技场或设置会话且仍在配置大厅；立即刷新后只安排一次 15 tick 选择性复核，不再由旧延迟任务清空整个背包。刷新只回收带 BedWars 命令标记的旧物品，逐项解析配置，坏项不会中断后续返回物品。槽位解析与代理返回优先级为纯逻辑组件，避免依赖 YAML 偶然顺序。正式 API 的 `applyLobbyState` 使用新入口，既有 `sendLobbyCommandItems` 则保留其已公开的延迟全清契约，避免补丁版本破坏附属插件。主配置架构 26 还把历史架构 15 的破坏性 `leave` 删除限定为一次性备份恢复，并停止未来架构升级反复创建管理员已经删除的节点。

7.1.0 把方块所有权改为事件结束后的单次延迟对账：监听器只记录本 tick 候选，下一 tick 根据最终取消状态和真实 `BlockData` 提交索引，不引入周期扫描，也不会被同优先级后置反作弊制造假阳性或假阴性。地图区域保护和玩家方块所有权由纯策略方法组合，玩家方块优先；爆炸使用同一不变量。离场防重按 UUID 生命周期封装，成功重连显式恢复，`KICKED` 退出才放弃重连。TAB 的 nullable 名称与逐查看者观察者模式分别缓存、失败分别重试，释放所有权时从 Paper 当前快照一次恢复，真实游戏模式和旁观物品流程不变。

9.0.1 起恢复逐查看者的完整 PlayerInfo 显示名，并与 scoreboard Team 的头顶名牌职责分离；显示名缓存记录“前缀 + 明确队伍色玩家名 + 后缀”，事件刷新和分批低频重放共用同一渲染结果。9.0.3 恢复玩家行中的队伍占位符解析；当前公开版本 4.1.8 只维护简体中文内置语言，进行中的存活玩家及三类结算队伍行默认前缀统一为 `{teamColor}{teamName} `，语言架构迁移只替换已知中文内置值，管理员模板保持不变。

## 仍然存在的技术债

### Arena 类职责过多

`Arena` 仍有约 2860 行，同时管理注册表、玩家生命周期、游戏状态、世界、任务和聊天辅助。4.1.9 已将主大厅状态、命令物品解析、槽位冲突与延迟复核抽取到 `LobbyService`，并保留 `Arena` 的兼容入口。后续应继续按注册表、玩家会话和状态机逐步拆分，但一次性重写风险很高。

`DamageDeathMove` 仍然同时承担死亡判定、旁观、重生、移动限制和伤害规则。下一批低风险重构应继续提取无状态的死亡分类与重生位置决策，再迁移会产生 Bukkit 副作用的流程。

### 大量静态全局状态

配置、竞技场注册表、语言和部分缓存使用静态字段，增加测试隔离和热重载难度。项目已经明确禁止热重载；长期可改为由主插件持有的服务对象。

### 旧 Bukkit API

聊天仍基于已弃用的 `AsyncPlayerChatEvent`。未来可直接迁移到 Paper Adventure 的异步聊天事件，并以 `Component` 构建消息，减少颜色字符串拼接；无需考虑低版本 Bukkit 回退。

### 配置路径依赖字符串

竞技场、商店和升级中仍有不少动态字符串路径。可逐步增加类型化配置记录与校验报告，但必须保持现有 YAML 兼容。

### 部分异常被忽略

商店默认物品和配置解析中仍存在宽泛 `catch (Exception ignored)`。后续应改为带配置路径的限频警告，既保留容错，也让管理员能定位错误。

### 无用代码与依赖审计边界

4.1.9 的生产类引用扫描只发现 `InvalidSoundException` 没有仓库内调用方，但该类型位于已发布的 API 模块，删除会破坏附属插件的二进制兼容，因此继续保留。Maven 依赖分析把 `slf4j-simple` 标记为源码未直接使用；它实际为已隔离打包的 HikariCP 提供运行时日志绑定，也不能删除。后续清理必须同时检查公开 API、反射/服务加载和 shade 后运行时用途，不能只凭文本引用次数删除。

## 推荐的下一批 API

以下内容值得后续增加，但本次没有贸然暴露内部实现：

1. 类型化的死亡上下文 API：区分普通、虚空、最终死亡和有效攻击者。
2. 安全出生点解析服务：允许附属插件复用趴下/邻近安全点算法。
3. 地图生命周期服务：以只读状态报告备份、卸载、恢复和启用进度。
4. 类型化配置校验结果：返回错误路径、严重级别和修复建议。
5. 大厅保护扩展点：让附属插件登记允许交互的自定义物品或 GUI。

新增 API 时应遵循：优先不可变快照、明确可空性、避免暴露实现类、保持主线程约束文档、保留旧接口至少一个兼容周期。

代码安全边界、已修复漏洞和部署建议另见[安全审计与部署加固](security-audit.md)。
